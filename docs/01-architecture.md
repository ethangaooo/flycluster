# 架构与记忆模型

## 一、服务拓扑

| 服务 | 端口 | 职责 | 关键约束 |
|---|---|---|---|
| `services/orchestrator` | 8800 | 环境推进、观测分发、消息路由、记账评分、对外开放 API、托管控制台 | **不替脑节点计算动作**；唯一持有环境事实 |
| `services/brain` | 8000 | 一个果蝇脑实例：连接组子图 + LIF 脉冲核 + 本地记忆 + 记忆适配器 | 每个容器一个实例，状态互不共享 |
| `services/memory_hub` | 8100 | 经验汇集、检索、冲突、版本、回放 | 数据落独立持久化卷；防回声 |
| `services/env` | 8200 | 共同环境与评估，可被替换/远端运行 | 所有对照看到完全相同的观测序列 |

所有服务共用一个镜像，compose 里用 `command` 区分角色——避免脑节点与对照模型跑在不同代码版本上。

### 为什么是"编排器集中持有环境"

单机原型阶段，环境与日志必须在一个地方，否则无法保证所有对照拿到同一个任务实例。
脑节点只接收 105 维观测向量与若干条同伴消息，不知道全局地图——这正是任务要考察的"局部观察"。

## 二、一层数据流（一个 tick）

```
env.observe(i)                       → 105 维局部观测（含感知失效时的全零帧）
brain.prepare()                      → 线索向量 cue = CueEncoder(obs)   [固定投影，与结构无关]
brain.recall()                       → 本地检索 k_local 条 + 中心检索 k_central 条
brain.compose_current()              → 三路电流分别注入互不相交的神经元组
      ├─ 传感组  sensor  (96 个)  ← 固定随机投影(obs)
      ├─ 记忆组  memory  (24 个)  ← 检索结果经固定适配器
      └─ 同伴组  peer    (24 个)  ← 同伴消息 int16 解码后投影
net.simulate(20 步)                  → LIF 脉冲仿真 + 遥测（实时比/丢弃/NaN）
readout.scores(读出组脉冲计数)         → 5 个动作分数 → argmax（含 ε 探索）
message.encode(消息输出组脉冲)         → 8 × int16
brain.build_record() + remember()    → 本地记忆落盘，选择性提交中心
```

三路电流注入**互不相交的神经元组**，这不是美观问题：消融时要能单独关掉任一路，
并逐路上报贡献计数，否则无法区分"协作收益来自传感、来自回忆，还是来自同伴"。

## 三、连接组层

### 3.1 图的三个来源

| 来源 | 说明 | 许可 |
|---|---|---|
| `synthetic-<n>` | 程序化合成，对齐果蝇全脑的拓扑统计量 | CC0-1.0 |
| `<name>.npz` | 由 `tools/fetch_connectome.py` 从官方 neuPrint 或本地导出文件生成 | 随数据（默认 CC-BY-4.0） |
| `synthetic-<n>-rewired` | 上面对照图的保度序列重连版本 | 同父图 |

### 3.2 保度重连（对照组的核心）

用有向 Maslov–Sneppen 双边交换构造对照图，**保持**：

- 节点数
- 二值化入度序列
- 二值化出度序列
- 抑制神经元集合（符号随源神经元走，天然保持）
- 权重多重集合（整体重排，不重新抽样）
- 输入→输出可达性（不可达就换种子重试，记录接受轮次）

**重连破坏的是**：模块化结构、富俱乐部组织、局部模体组成，以及"读出神经元的预神经元是否来自感觉组"
这一身份信息。

> 实测：合成图模块化 0.53 → 重连后 -0.003，而全局递归性（最大强连通分量占比）两者都接近 1。
> 也就是说，本对照主要改变的是**模块与局部组织**，不是全局递归程度。报告里必须这样写。

### 3.3 输出方差与保度重连的代价

重连是实验里最耗时的一步（2000 神经元约 1.6 秒，50k 神经元会显著更慢）。
`rewire_matched` 的 `max_attempts` 与 `swap_multiplier` 可调，但**不允许**通过降低可达性要求来加速。

## 四、神经内核

电流型 LIF，稀疏 CSR 传播，向量化 numpy。

| 参数 | 默认 | 说明 |
|---|---|---|
| `dt_ms` | 1.0 | 时间步 |
| `tau_m_ms` / `tau_syn_ms` | 20 / 5 | 膜时间常数 / 突触时间常数 |
| `synaptic_scale` | 0.35 | 全局突触增益，用于把网络从饱和区拉到输入敏感区 |
| `background_current` | 14.0 | 背景电流（稳态等效值） |
| `noise_sigma` | 6.0 | 逐神经元高斯噪声 |
| `max_spikes_per_step` | 0 | 单步脉冲上限；超出部分计入 `dropped_spikes` |

**稳态等效语义**：注入值 `c` 意味着 `i_syn` 的稳态值约为 `c`（内部乘 `1 - exp(-dt/tau_syn)`）。
这样调参时"输入相对背景多大"是直接可读的。

### 4.1 一个曾经真实发生、现在由测试守住的缺陷

邻接矩阵 `matrix()` 用 `[src, dst]` 索引是为了图算法（行向量右乘做可达闭包），
而脉冲传播需要 `propagation_matrix()` 的 `[dst, src]`。用错方向会让脉冲沿反向传播，
症状是**输入对读出毫无影响**——网络看起来在放电，但感觉信息永远到不了输出。

`tools/smoke_test.py` 里的「神经内核：突触传播方向」用"提高感觉增益后读出组放电率是否显著变化"
守住这条：当前实测 0.01301 → 0.02602（×2.00）。

## 五、记忆模型（四层 + 一条闭环）

| 层次 | 保存什么 | 放在哪里 | 如何共享 |
|---|---|---|---|
| **L1 即时工作记忆** | 当前动作、近期线索、膜电位摘要 | 各脑运行内存（`WorkingMemory`） | **不共享**，只通过通信输出间接表达 |
| **L2 个体经历记忆** | 位置、动作、结果、感知是否有效 | 各脑本地 JSONL（`LocalMemory`） | 选择性提交中心 |
| **L3 个体技能记忆** | 学习参数本身（读出器 ΔW） | 各脑进程内 | 不进中心；可通过经验回放间接传播 |
| **L4 群体共享记忆** | 原始经验、冲突、版本、来源链 | 中心 `MemoryHub`（SQLite + 卷） | 按任务/范围/权限检索分发 |

### 5.1 记忆怎样真正进入神经计算

```
当前观测与内部状态 → 检索相关经验 → 经 MemoryAdapter 编码为记忆输入
                   → 改变脑内计算 → 产生行动 → 获得反馈 → 更新记忆或学习参数
```

"经验编码为记忆输入"这一步不能省略：**数据库里有记录，不等于脑模型用上了它**。
检索到的记录只有经过固定投影变成电流、注入记忆神经元组，才真正参与本步计算。

研究模式下适配器**不返回**"这一步该往左转"的最终指令，也不在内部跑规划器。
否则必须把该规划器单独纳入贡献评估。

### 5.2 防回声：为什么需要 `origin_event_id`

```
A 产生经验 evt-1  →  提交中心（原始，evidence +1）
B 检索到它        →  采纳了 A 的结论 → 记为 inference，evidence 不增
B 把同一条转发回中心 → 中心识别：同一 origin_event_id、不同 producer、自称原始
                     → 标记 is_echo，echo_of 指向原记录，evidence 不增
```

判定规则（`MemoryStore.submit`）：

1. 同 `(origin_event_id, producer_node)` 重复提交 → 拒绝，不增加证据。
2. 同一 `origin_event_id` 由**另一个**节点提交且自称原始观察 → 判为回声，不增加证据。
3. 采纳了检索结论的派生经验（`kind=inference` 或有 `derived_from_origin`）→ `is_primary=0`，不增加证据。

> 关键细节：**仅仅是"检索返回过上下文"不构成派生**。若按"parents 非空即派生"判定，
> 几乎所有经验都会被误判为转发，证据计数会系统性塌成 1。

### 5.3 事件序号：为什么不能用墙钟排序

快照与过期经常落在**同一毫秒**内。用 `valid_to > snapshot_time` 这类比较，会给出错误答案
（早期版本就踩过这个坑，快照回溯返回 0 条）。

现在用单调递增的事件序号（`seq` / `expire_seq`）：

- 查询 head：`expire_seq IS NULL`
- 按快照 S 回溯：`seq <= S.seq AND (expire_seq IS NULL OR expire_seq > S.seq)`

语义与时钟分辨率彻底解耦。`_migrate()` 会为早期建的库补列并对齐历史数据。

### 5.4 范围隔离

`memory_scope` 四级：`run` / `session` / `project` / `tenant`。

- `scope=run` 且**未指定** `run_id` → SQL 层拼 `AND 1 = 0`，一条都不返回。
  "没传参数就默认跨运行共享"是最容易出的数据泄漏，必须从最底层堵死。
- 高于 `run` 的范围必须显式提供 `tags.tenant`，否则 `POST /v1/runs` 直接 400。

### 5.5 检索计费

中心记忆**本身是一条通信通道**。查询返回的字节数（`query_cost_bytes`）会被累加进
`memory_bytes_in` 并出现在报告里。否则表面上脑间只有低带宽消息，
实际上却通过共享数据库获得了无限信息，实验失去公平性。

## 六、对照组的公平性机制

全部实现都通过 `services/shared/node_common.py` 走同一份记忆/通信/记录代码，
唯一允许各自实现的是 `comm_values()`（消息输出）与动作决策。

| 机制 | 位置 | 为什么 |
|---|---|---|
| 同一线索函数 | `flycore/coding.py:CueEncoder` | 否则记忆检索的差异会混进模型差异 |
| 同一消息量化 | `NodeCommon.make_message` | 带宽口径一致 |
| 同一奖励规则 | `services/orchestrator/runner.py` | 学习预算可比 |
| 同一探索率 | `BrainNodeConfig.exploration_epsilon` | 未训练读出器会锁死在单一动作 |
| 可训练参数量上报 | `health()["trainable_params"]` | "同预算"需要可核对 |
| 同一外部信息向量 | `NodeCommon.external_features` | 对照组与脑模型看到同样的信息量 |
