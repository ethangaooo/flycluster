# 实验协议与三道门

## 一、第一阶段只回答一个问题

> 在局部观察、有限通信的协作搜索任务中，果蝇连接组派生回路，能否比同预算的普通回路
> 或经典策略带来**可重复**的收益？

暂时不同时追求语言理解、数学推理、通用智能、实体机器人和全脑生物真实性。

**任务**（默认可通过 CLI / API 改）：

| 项 | 默认值 | 说明 |
|---|---|---|
| 网格 | 32 × 32 | 随机障碍 12% |
| 智能体 | 4 | 之后测试 2 与 8 |
| 局部观测 | 5 × 5 × 4 通道 + 姿态 + 进度 = 105 维 | 看不到全局地图 |
| 目标 | 6 个隐藏目标 | 需要走到格子上才算拾取 |
| 步数上限 | 120（筛查） | 1 步 = 20 ms 神经仿真 |
| 消息 | 每条 8 × int16，每步至多一条 | 4 节点 5 Hz → 理论 320 B/s |
| 内部状态 | 每个实例独立 | 只共享只读连接结构 |

**评分 S** = `10×命中 − 0.5×碰撞 − 0.2×重复探索 + 5×覆盖率`。
权重是工程选择，全部对照使用同一套。

## 二、主对照：11 个组

| 组 | 中间结构 | 通信 | 回答的问题 |
|---|---|---|---|
| `real_comm` | 连接组子图 | 开 | 主实验组能否完成任务 |
| `real_nocomm` | 连接组子图 | 关 | 收益是否来自通信 |
| `rewired_comm` | 保度重连 | 开 | 真实连接结构是否有独特贡献 |
| `rewired_nocomm` | 保度重连 | 关 | 同上 |
| `reservoir_comm/nocomm` | 随机储备池（512 单元） | 开/关 | 普通时序模型能否更便宜地完成 |
| `gru_comm/nocomm` | 单层 GRU（64 隐单元） | 开/关 | 同上 |
| `classical` | 无神经网络 | 关 | 是否根本不需要神经网络 |
| `classical_comm` | 无神经网络 | 开 | 通信对非神经策略是否有用 |
| `noop` | 移除脑模型，只留相同接口与读出 | 关 | 实际解题能力是否来自外围代码 |

所有组的差别**只有**中间结构与通信开关。观测、动作集、消息权限、奖励规则、探索率、
读出器预算完全一致；可训练参数量在 `health()` 中上报以便核对。

## 三、交互效应 Δ（核心指标）

```
Δ = (S_真实结构,有通信 − S_真实结构,无通信) − (S_重连结构,有通信 − S_重连结构,无通信)
```

它区分两件不同的事：

- **"通信对所有网络都有效"** —— Δ ≈ 0，正确的结论是「该协作方法有效」。
- **"真实果蝇结构特别有利于利用通信"** —— 需要 Δ > 0 且 95% 置信区间下界 > 0。

Δ 为正也不自动等于商业优势：还要看主实验组是否优于最好的普通模型，以及多花了多少成本。

实现：`flycore/scoring.py:paired_ci_delta`，按种子配对计算，四组必须同种子、同任务、同步数。

## 四、三道门

### 门 1：实现可信

| 判据 | 阈值 |
|---|---|
| 实时比（模拟时间 ÷ 现实时间，取最慢节点） | ≥ 0.05 |
| 脉冲丢弃率 | ≤ 0.001 |
| NaN / Inf 事件 | = 0 |
| 数值有界 | True |
| 相同版本、种子、输入可重复 | 必须 |

对照模型没有脉冲仿真，门 1 改以确定性复现与数值有界为准（报告中会标注 `has_spiking_simulation: false`）。

### 门 2：确实有任务收益

先用 **≥3 个种子**筛查，不凭一条最佳曲线下结论。候选结果可以是更高成功率、更少训练交互，
或者感知失效下更稳定，但**主要指标必须提前选定**。

通过筛查后扩到 **≥10 个独立种子**，保留环境评估与置信区间分析。

> 真实结构与重连结构若无差异，结论必须限定为「该协作方法有效」，而不是「果蝇脑有特殊优势」。

### 门 3：值得继续花钱

初期门槛：配对种子数 ≥10 且 Δ 的 95% CI 下界 > 0。
后期投入门槛（原计划保留）：相同质量成本减半，或同预算成功率提高 10 个百分点。

**初期还应当接受一种有价值的结果**：优势只存在于某种噪声条件、记忆长度或通信预算下——
那就把研究缩小到一个专用问题。

反向结论同样要执行：

- 普通小模型在同等质量下更便宜 → **停止扩大脑模型**。
- 演示有趣但指标没有收益 → 归类为**演示成果**。

## 五、投入分两次批准

| 阶段 | 投入上限 | 必须产出的结果 |
|---|---|---|
| 第 1—2 天 | 4—8 人时；不购置硬件 | 固定版本、检查许可、运行单实例、记录吞吐与稳定性 |
| 第 3—5 天 | 8—12 人时 | 共同环境、经典基线、小模型基线、一致的评分方法 |
| 第 6—10 天 | 8—20 人时；新增现金 ≤300 元 | 4 实例协作、通信消融、重连筛查、完整失败记录 |
| 通过后 | 再批准硬件；新增现金 ≤2000 元 | 2—4 节点硬件在环，以及实测延迟、能耗、异常记录 |

人时必须单列。如果前几天连稳定复现都没完成，**先说明阻塞原因**，不要为了凑计划继续加功能。

## 六、实验 A：一个脑是否真正从经历中改变行为？

关联任务：固定关卡布局反复重置（同一 seed 保证目标位置可复现），比较三种配置：

| 配置 | 本地检索 | 中心记忆 | 学习模式 |
|---|---|---|---|
| `A0_no_memory` | 关 | 关 | readonly |
| `A1_local_recall` | 开 | 开 | readonly |
| `A2_recall_plus_learn` | 开 | 开 | plastic |

**两个保留测试必须分开报告**：

| 测试 | 做法 | 支持的结论 |
|---|---|---|
| 保留测试 1（持久化） | 同 `node_id` 重建引擎（等价进程重启），检查能否检索到旧记录 | 经验被持久化了 |
| 保留测试 2（学习参数） | 清除 L1 工作记忆、关闭全部检索、清空 hub，只留 ΔW | 改善进入了学习参数 |

两者不能混为一个指标。而且本项目的 A2 只更新**外围读出器** ΔW，
所以结论只能表述为「外围读出器学到了东西」——要谈"脑内学习"，必须另行更新脑内可塑性参数
并通过对应测试。

运行：`python experiments/run.py A --seeds 2`

## 七、实验 B：一个脑的经验能否有效帮助另一个脑？

阶段 1：教师节点在任务上跑若干 episode，经验进入中心（范围 `project`）。
阶段 2：学生节点（全新实例）在五个条件下评估：

| 条件 | 设置 | 检验 |
|---|---|---|
| `B0_no_share` | 不接中心、不检索 | 基线 |
| `B1_share_same_env` | 接中心，同环境 | 共享有没有帮助 |
| `B2_share_other_env` | 接中心，**不同关卡但同一 task_id** | 无关经验是否被误当有用 |
| `B3_expired` | 教师经验标记过期后再评估 | 过期经验是否被排除 |
| `B4_echo_guard` | 把教师记录以另一节点名义重投 | 转发是否被误计为独立证据 |

`B2` 的实现要点：把 `task_id` 手工设为相同字符串、只改 `seed`，这样经验能被检索到但实际无帮助。

## 八、实验 C：多个脑能否组合各自不完整的经验？

用 `TaskSpec.visibility_regions` 把网格切成左右两半：0/1 号节点**只看得见**左半区的目标，
2/3 号节点只看得见右半区。任何单个节点都不掌握完整信息。

| 条件 | 直接通信 | 中心记忆 | 中心规划器 |
|---|---|---|---|
| `C0_none` | 关 | 关 | 关 |
| `C1_peer_only` | 开 | 关 | 关 |
| `C2_memory_only` | 关 | 开 | 关 |
| `C3_peer_and_memory` | 开 | 开 | 关 |
| `C4_plus_central_planner` | 开 | 开 | 开 |

结论归属规则：

- `C3 − C0` 才是"互补信息整合"的增量。
- `C4 − C3` 是中心规划器的边际贡献。**若只有 C4 显著更高**，能力应归因于
  「脑集群 + 中心规划器」组合系统，**不是**脑间自主涌现。

## 九、记忆边界（所有实验通用）

必须明确写清四个边界，否则指标不可比：

1. 训练阶段写入了什么
2. 测试前允许携带哪些经验
3. 测试中允许学习什么
4. 不同测试回合之间是否保留记忆

允许持续学习没有问题，但**不能把先前测试的答案无意泄露给后续测试**。

## 十、通信与记忆预算的记账口径

```
理论值（文档口径） = n_senders × 8 × 2 字节 × 频率     # 4 节点 5 Hz = 320 B/s
实测发出量         = 实际发出消息数 × 8 × 2 字节 ÷ 运行秒数
检索返回量         = Σ memory_bytes_in                 # 中心记忆是一条通信通道
```

理论值不含报头、重传，以及"发给多个邻居造成的重复传输"。三者在报告里并列出现。

## 十一、分条件优势搜索（主对照未通过时该做的事）

主对照在真实连接组上给出 Δ = +5.05、区间跨 0。这种情况下"把模型做大"是错的，
正确动作是**缩小研究问题**：

> 优势只存在于某种噪声条件、记忆长度或通信预算下——那就把研究缩小到一个专用问题。

于是把"找优势"本身做成受控流程：

```bash
python experiments/run.py scan --axis perception \
    --values 0.0,0.25,0.5,0.75 --seeds 4 --replicate-seeds 4 \
    --ticks 200 --connectome male-cns-gateway
```

可选轴（定义在 `experiments/scan.py` 的 `AXES`）：

| 轴 | 含义 | 默认条件值 |
|---|---|---|
| `perception` | 感知失效比例（映射为 `perception_fraction = 1 - v`） | 0 / 0.25 / 0.5 / 0.75 |
| `comm_loss` | 消息丢弃率 | 0 / 0.2 / 0.5 / 0.8 |
| `comm_latency` | 消息延迟（决策步） | 0 / 2 / 5 / 10 |
| `local_memory` | 本地经验检索条数 `k_local` | 0 / 2 / 8 / 16 |
| `central_memory` | 中心经验检索条数 `k_central`（记忆通道开启） | 0 / 2 / 6 / 12 |

每个条件跑四个核心组（真实/重连 × 有通信/无通信），逐条件计算 Δ 与置信区间。

### 为什么必须自动复现，而不是挑最好的那个

扫描 K 个条件，即使真实效应为零，也会有约 `0.05K` 个条件的 95% 区间偶然不跨 0。
直接挑出最好的一个并报告，就是 **p-hacking**——只不过发生在"条件"这个维度上。

因此扫描器的判定规则是：

1. 探索阶段在种子集 A 上扫 K 个条件，标出区间下界 > 0 的候选；
2. **在不相交的种子集 B 上复现**这些候选（种子重叠会被直接判为无效）；
3. 只有两次都区间下界 > 0 的条件才算成立。

这比 Bonferroni 校正更强，也不需要新的统计代码。判定结果是三选一：

| 判定 | 含义 |
|---|---|
| 无候选 | 该轴上没有值得进入复现阶段的信号，按协议不应据此继续投入 |
| 有候选未复现 | 判定为多重比较造成的假阳性，**不支持**任何条件优势 |
| 有条件复现 | 是**局部条件优势**，不是普遍优势。必须把结论限定在这些条件下，并说明它不适用于未扫描到的条件 |

复现成功的条件，下一步应做**机制解释**与在该条件下的独立验证，而不是立刻扩大规模。

## 十二、跑法与产出

```bash
python experiments/run.py main --seeds 10     # 主对照（11 组 × 10 种子）
python experiments/run.py A --seeds 2         # 实验 A
python experiments/run.py B --seeds 2         # 实验 B
python experiments/run.py C --seeds 2         # 实验 C
python experiments/run.py scan --axis perception --seeds 4 --replicate-seeds 4
python experiments/run.py all --seeds 3       # 全部
python experiments/run.py main --quick        # 小规模链路验证，结论不可用
```

产出写入 `artifacts/`：完整 JSON（含逐种子明细与遥测）+ 可读 Markdown 报告。
报告模板强制包含：分组结果表、Δ 与置信区间、筛查结果、三道门、可信度遥测、通信与记忆预算、能力归因。
扫描报告另含：多重比较提示、不相交种子的复现结果、以及"局部条件优势 ≠ 普遍优势"的措辞约束。
