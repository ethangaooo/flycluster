对齐的拓扑统计量（都写在 `ConnectomeMeta.notes` 里）：

| 统计量 | 目标 | 实测（n=2000, seed=0） |
|---|---|---|
| 平均入度 | 重尾分布，均值 ≈ 40–50 | 49.7 |
| 模块化 Q | 显著大于 0 | 0.531 |
| 抑制性比例 | ≈ 12% | 12.0% |
| 递归性（最大 SCC 占比） | 高 | ≈ 1.00 |
| 富俱乐部 | 少数高连接度枢纽 | 通过 `hub_fraction=5%`、`hub_gain=6` 构造 |
| 感觉→运动上行通路 | 存在且非平凡 | 显式构造（`ascending_per_output=32`，权重 ×4） |

**必须显式声明的人为建模选择**（`ConnectomeMeta.dynamics_modeled = True` 恒为真）：

- 神经元动力学（LIF 参数）不是果蝇实测生理值
- 递质符号只区分兴奋/抑制，不含受体动力学、神经调质、缝隙连接
- 权重分布是人为设定的对数正态，不是实测突触强度
- 不包含视叶与复眼感光通路（`includes_optic_lobe = False`）

> 为什么必须显式构造上行通路：若输入到读出之间只靠多跳递归传播，感觉扰动会被整个网络的
> 平均效应吞掉，任务在结构上无法完成——那不是"结构劣势"，而是把模型建坏了。真实果蝇连接组中，
> 感觉上行神经元到下降神经元存在明确、相对直接的通路。

## 二、真实连接组（可选，经官方通道）

### 2.1 在线：官方 neuPrint API

```bash
pip install -r requirements-connectome.txt
export NEUPRINT_TOKEN=xxxx          # 在 https://neuprint.janelia.org 账户页生成

# 先探测：确认能连上、能查到哪些神经元类型
python tools/fetch_connectome.py probe --dataset male-cns:v1.0

# 再抓取（注意正则是全串匹配，要写 ^DN.* 而不是 ^DN）
python tools/fetch_connectome.py online --dataset male-cns:v1.0 \
    --out data/male-cns-gateway.npz \
    --descending-regex '^DN.*' --ascending-regex '^AN.*'
```

工具使用 `neuprint-python`（实测版本 0.3.5）的 `Client` / `SegmentCriteria` /
`fetch_neurons` / `fetch_adjacencies` / `fetch_custom`。

**两条纪律**：

1. **绝不静默回退**：拿不到真实数据就报错退出，不会偷偷用合成图冒充真实连接组。
2. **许可随数据走**：数据集名、许可、来源全部写进 `ConnectomeMeta` 并落盘留痕。

### 2.1.1 实测踩到的四个坑（都会静默给出错误结果）

| 坑 | 症状 | 正确做法 |
|---|---|---|
| **type 正则是全串匹配** | `SegmentCriteria(type='^DN', regex=True)` 返回 **0 个**神经元，看起来像"数据集没有下降神经元" | 写 `'^DN.*'`。`^DN` 只能匹配字符串恰好等于 `DN` 的情况 |
| **`fetch_adjacencies` 上游缺陷** | 抛 `TypeError: unsupported operand type(s) for -: 'object' and 'int64'`（`NotPrimary` 行为空时 `eval` 失败），与数据和参数都无关 | 改用 Cypher 直接取边（见下）；`weight` 属性本身已是跨 ROI 聚合值，反而更简单 |
| **邻接表按 ROI 拆分** | 多 ROI 的连接在去重时被压成只保留一条，权重被系统性低估 | 先 `groupby([pre, post]).sum()` 汇总，再映射到节点索引 |
| **macOS 上装不上** | `pip install neuprint-python` 报 `EEXIST: mkdir ... asciitree_...`（sdist 内大小写冲突） | 加 `--only-binary=:all:` |

### 2.1.2 子图裁剪最容易写反的一处语义

`keep_io_reachable` 的语义是**条件式**的：只在"输入→输出不可达"时才按权重剪枝。

如果把它写成"最小化边集"（二分搜索找最小可达子集），本来就可达的图也会被砍到只剩一条最短通路——
实测 891 个节点 28,615 条边的真实子图被压成 525 条边、平均入度 0.59、最大强连通分量 3.5%，
递归结构与局部循环全部消失。那样的"真实连接组"拿去做实验没有意义。
正确的顺序是：**先判断全量图是否可达，可达就一条不删。**

### 2.1.4 子图是怎么选出来的

```
上行组 AN*  ──┐
              ├─→ 一跳中间神经元（Cypher：同时接受 AN 输入、向 DN 输出）
下降组 DN*  ──┘        │
                       ▼
        节点集 = AN ∪ DN ∪ 中间神经元
                       │
                       ▼
        Cypher 取子图内部全部连接（按预神经元分批，配对集为全体，跨批不漏）
                       │
                       ▼
        再补 1 跳强连接的前驱/后继（下游优先），换真实递归结构
                       │
                       ▼
        全量图可达 → 一条不删；不可达 → 才按权重剪枝
```

选这一条路线而不是"把 AN 和 DN 直接连起来"的原因：直接连接会得到一个几乎没有内部结构的
两层图；而"优先保留从输入到输出的路径和局部循环"是构思文档对子图选取的明确要求。

### 2.1.5 已接入的两张真实子图（可复现参数）

库里共 **176,422 个神经元**。「取多少」是参数选择，不是数据上限；真正的约束是
**仿真实时比必须 ≥0.05**（门 1）。两张图当前都可用：

| | `male-cns-gateway` | `male-cns-large` |
|---|---|---|
| 神经元 | 891 | **6,000** |
| 聚合连接边 | 28,615 | **342,126** |
| 平均入度 | 32.1 | 57.0 |
| 最大强连通分量 | 92.8% | **96.5%** |
| 抑制性比例（GABA 实测） | 29.2% | 27.7% |
| 聚合突触总数 | 919,885 | 9,051,634 |
| 纳入的上行 / 下降神经元 | 60 / 48（抽样） | **1,849 / 1,342（全部）** |
| 模块标签 | `class`，4 类 | `class`，14 类 |
| 文件大小 | 76 KB | 1.0 MB |
| 单步仿真 | 0.04 ms | **0.22 ms** |
| 实时比（单节点基准） | 31.2 | **4.71** |
| 保度重连耗时 | 0.4 s | 6.7 s |

两张图都**无需剪枝**（全量边下输入→输出已可达）。`male-cns-large` 的实时比比门 1 阈值
高约 **94 倍**，还有很大余量——真正先到瓶颈的是主对照里的多节点并行，
实测 4 节点同时跑时实时比降到 1.65。

### 2.1.6 抓取耗时与已知瓶颈

| 方案 | 节点 | 耗时 | 结论 |
|---|---|---|---|
| AN/DN 抽样 + 1 跳中间神经元 + 1 跳扩展 | 891 | ~45 s | 快，适合迭代 |
| **全部 AN/DN + 2 跳扩展（跳过 2 跳查询）** | **6,000** | **11 min** | 当前推荐的最大规模 |
| AN/DN 抽样 + 2 跳中间神经元查询 + 2 跳扩展 | 10,000 | >8 min 无进展 | **放弃** |

**瓶颈在 2 跳中间神经元查询**：`MATCH (a)-[:ConnectsTo]->(m)-[:ConnectsTo]->(d) WHERE a.bodyId IN [...] AND d.bodyId IN [...]`
在 17 万神经元的库上会展开巨量路径，而 `d.bodyId IN [几百个 id]` 的过滤发生在展开之后。

**若要继续扩大，应改扩展查询的写法**：现在每条扩展查询都带
`b.bodyId IN [几千个 id]`，这个大 IN 列表是主要开销。改成
「不约束配对集合、靠 `ORDER BY weight DESC LIMIT n` 截断，客户端再去重」会快得多。

### 2.1.7 已接入的真实子图（可复现参数）

```bash
python tools/fetch_connectome.py online --dataset male-cns:v1.0 \
    --out data/male-cns-gateway.npz --name male-cns-gateway \
    --max-input 60 --max-output 48 --intermediate-limit 400 \
    --expand-hops 1 --expand-batch 300 --node-budget 900 --min-synapses 5
```

产出 `data/male-cns-gateway.npz` 的实测统计：

| 指标 | 数值 | 对照：合成图 `synthetic-2000` |
|---|---|---|
| 神经元 | 891（上行组 60 + 下降组 48 + 中间/扩展 783） | 2,000 |
| 聚合连接边 | 28,615 | 105,647 |
| 平均入度 | 32.1 | 49.7 |
| 最大强连通分量占比 | **92.8%** | ≈100% |
| 抑制性比例（GABA） | **29.2%** | 12.0% |
| 模块度（按真实 `class` 标注，4 类） | 0.0075 | 0.531（按合成模块标签） |
| 聚合突触总数 | 919,885 | — |
| 许可 | CC-BY-4.0 | CC0-1.0 |

**两处必须如实说明的差别**：

1. **抑制性比例是 29.2%，不是构思文档假设的 12%。** 该值由数据自带的 `predictedNt`
   递质预测得出（GABA 判为抑制），未经人工补注。合成图的 12% 是建模假设。
   这个差别会直接改变网络的兴奋/抑制平衡，是"用真实数据"最实质的收益之一。
2. **`class` 标签太粗（只有 4 类），按它算出的模块度在真实图与重连图上都接近 0**
   （0.0075 vs 0.0072）。因此本对照在真实数据上主要改变的是**每个神经元的预神经元身份
   与局部模体组成**，而不是由 `class` 衡量的模块度。报告里不能声称"重连破坏了模块化"。

### 2.2 离线：本地导出文件

```bash
python tools/fetch_connectome.py offline \
    --connections data/male-cns/connections.csv \
    --neurons data/male-cns/neurons.csv \
    --out data/male-cns-gateway.npz
```

- 支持 CSV / Parquet，支持逗号分隔多文件或 `--glob` 通配。
- 列名自动识别（`bodyId_pre` / `pre` / `source` / `from` …；`bodyId_post` / `post` / `target` / `to` …；
  `weight` / `syn_count` / `count` …）。**识别不出就报错，不猜**。
- 也可以把在别的机器上获得的导出文件直接带来，不需要联网。

### 2.3 接入时的口径换算

| 环节 | 处理 | 说明 |
|---|---|---|
| 突触数 → 权重 | `weight = log1p(syn_count)` 后归一化到均值 1 | 压缩重尾，与合成图同量纲 |
| ≥ 过滤 | `--min-synapses`（默认 3） | 去掉单突触噪声连接 |
| 递质 → 符号 | `predictedNt` 含 `gaba`/`gad` → 抑制 | 谷氨酸是否计入抑制由 `--treat-glu-inhibitory` 控制 |
| 递质缺失补注 | `--inhibitory-fraction 0.12` 随机补注，并**标注为补充** | `notes` 里写明"非数据自带" |
| 可达性 | 若输入→输出不可达，按权重大到小保留边直到可达 | 丢弃超过 35% 时打印警告；**不允许降低可达性要求** |

### 2.4 计数口径统一（容易出错的地方）

| 说法 | 准确含义 |
|---|---|
| "127 万条边" | 神经元之间**聚合后**的连接边，不是 127 万个独立生物突触 |
| `edge_count` | 去重后的 `(pre, post)` 连接对数 |
| `synapse_count` | 原始数据里的突触总数（可能为 None） |
| `mean_indegree` | 二值化入度均值 |

后续比较 MaleCNS、FlyWire 与其他实现时，**必须统一到这个口径**，否则数字不可比。

## 四、关于爱因斯坦样本（长线，不作为本阶段前置条件）

**需要纠正的常见说法**：他的大脑主要是经过福尔马林固定、分块、火棉胶类材料包埋后制作组织切片，
**不是**完整冷冻保存、等待扫描恢复的脑。馆藏档案记载其中一批材料包括约 566 张脑组织切片，
厚度约 12—20 微米，采用髓鞘或尼氏染色。

关键差别不是"照片够不够高清"，而是**有没有记录足够完整的三维连接信息**。

重建目标必须分层：

| 目标 | 现有材料可能支持什么 | 还缺什么 |
|---|---|---|
| 宏观外形、脑沟脑回 | 历史照片 + 定位图建立带不确定性的解剖模型 | 完整准确的三维几何与组织变形校正 |
| 局部细胞层次与组织结构 | 对现存切片数字化、细胞分布分析 | 标本质量、采样连续性、可比性 |
| 个体特异的突触级连接组 | 需先判断现存组织是否适合进一步成像 | 大范围连续超微结构、跨组织块连接追踪 |
| 能运行并表现特定认知能力的模型 | 可研究由结构约束的候选计算模型 | 动力学参数、有效连接强度、学习规则、功能验证数据 |

**工程判断**：即使建立了某个人脑结构约束的网络，也应称为**候选计算模型**，再通过实验验证，
而不是默认它已具有这个人的知识与认知能力。同一份连接拓扑可能对应不同的有效连接强度、
神经元动力学、调制状态与学习过程。

更合理的人脑研究路线是**按数据可用性和可验证性选择样本，不按名气选择样本**。
MICrONS 小鼠项目（约 7.5 万神经元活动记录 + 同组织电镜重建配准）比"名气大的样本"更值得作为方法学参照，
因为可以同时问：连接是什么、活动是什么、模型能否预测活动。

**涉及实际标本还需要馆藏方授权、使用条件审查与专业机构合作。**
博物馆档案并不意味着可以自由取得或加工组织。
